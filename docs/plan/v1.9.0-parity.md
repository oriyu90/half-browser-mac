### 0.1 決定的な制約（設計を左右する）— **実測で確定**

VPN の実装方式を決めるため、3 つの経路を実際に試した。

| 経路 | 実測結果 | 結論 |
|---|---|---|
| NetworkExtension（`NEPacketTunnelProvider`） | クラスは存在し `loadFromPreferences` も成功するが、**トンネル開始には `com.apple.developer.networking.networkextension` entitlement が必須**。これには**有料の Apple Developer Program** が要る。本環境は `security find-identity` = **0 valid identities**（ad-hoc 署名のみ） | **不可** |
| `wg-quick up`（root で utun 作成 + ルート設定） | `wg-quick` は `[[ $UID == 0 ]] \|\| exec sudo` で**必ず root を要求**。本環境は `sudo` にパスワードが必要で**非対話実行不可** | **不可**（ユーザーが手動で `sudo` する場合のみ可） |
| `wireguard-go utun99`（非 root） | `Failed to create TUN device: operation not permitted` | **不可** |

→ **Android と同じ「アプリ内 VPN」は macOS では実装できない。** これは実装漏れではなく、
macOS のセキュリティモデル（VPN は署名済みシステム拡張か root が必須）による制約である。
したがって VPN は次の 2 段構えにする。

- **(A) 実装する**: WireGuard 設定の**取り込み・検証・保管（Keychain 暗号化）・エクスポート**、
  **疎通判定ロジックの完全移植**（純関数）、`wg` が使える場合の**ハンドシェイク時刻読み取り**、
  `wg-quick` が使える場合の**接続/切断**（ユーザーが権限を持つ場合）、**スリープ復帰・ネットワーク
  変化の検知**（これは root 不要）。
- **(B) 実装しない（理由を UI に明示）**: 自前トンネルの確立。設定タブに「macOS ではアプリ内
  VPN に署名済みシステム拡張が必要」と表示し、公式 WireGuard アプリの利用を案内する。
  **黙って機能を隠さない。**

> この判断は最終報告でも明示する。ユーザーが有料開発者アカウントを用意すれば (B) も実装可能で、
> その場合の設計は §5 に残す。

## 2. 実装計画

### 2.1 VPN プロファイル管理（F1）

**移植元**: `core/VpnConfig.kt`（509 行）、`data/VpnStore.kt`、`ui/settings/VpnSettingsTab.kt`

- `core/src/vpn_config.rs`（新規）: Android の `VpnConfig.kt` を Rust へ移植。
  - `parse(text) -> Result<ParsedVpnConfig, VpnConfigError>`
  - 検証: 空 / サイズ上限 / `[Interface]`・`[Peer]` の有無 / 秘密鍵・公開鍵の Base64 長と文字種 /
    エンドポイントの `host:port` 形式 / プリシェアドキー
  - 派生表示値: `addresses` / `dns` / `listenPort` / `mtu` / `peers`
  - **原文を保持**（エクスポートが公式 WireGuard でそのまま使える）
- `core/src/vpn_tuning.rs`（新規）: `tune()` — keepalive 25 秒挿入、MTU 1280 補正、DNS 先頭 3 件
- `cefapp/src/vpn_store.mm`（新規）: プロファイルの永続化。**秘密鍵を含むため Keychain に暗号化保存**
  （`kSecClassGenericPassword`、サービス `half-browser-vpn`）。バックアップには含めない。
- `cefapp/src/vpn_settings.mm`（新規）: 設定タブ「VPN」— 貼り付け / `.conf` 読み込み / 一覧 / 削除 /
  エクスポート / 接続・切断。

**制約の明示**: トンネルの確立自体は §0.1 の理由で不可。接続操作は `wg-quick` が導入済みで
かつユーザーが権限を持つ場合のみ実行し、無い場合は「macOS では署名済みシステム拡張が必要」と
ローカライズして案内する。**どの経路でもクラッシュしない**ことを必須とする（AC-10）。

### 2.2 VPN 疎通判定（F2）

**移植元**: `core/VpnHealth.kt`（280 行）— **純関数なので Rust へ 1:1 移植できる**

- `core/src/vpn_health.rs`（新規）:
  - `enum VpnReachability { Unknown, Verifying, Healthy, Stale, Unreachable, TunnelOnly }`（**順序を保つ**）
  - `VpnHealthSnapshot { profile_id, connected_at, last_handshake_at, checked_at }`
  - `classify(snapshot, now, grace_start_override) -> VpnReachability`
  - `next_poll_delay_ms(foreground, reachability, consecutive_healthy) -> u64`
  - `publish(observed, previous) -> VpnReachability`
  - 定数: `HEALTHY_WINDOW_MS=180_000`、`HANDSHAKE_GRACE_MS=45_000`、`POLL_FOREGROUND_MS=10_000`、
    `POLL_BACKGROUND_MIN_MS=60_000`、`POLL_BACKGROUND_MAX_MS=300_000`、`POLL_BACKOFF_FACTOR=1.5`、
    `NETWORK_CHANGE_GRACE_MS=10_000`、`AUTO_RECONNECT_MIN_INTERVAL_MS=30_000`、`MAX_BACKOFF_STEPS=16`
- **テストは Android の `VpnHealthTest` を 1:1 で移植**（同じ境界値・同じ期待値）。
- ハンドシェイク時刻の取得: `wg show <iface> latest-handshakes` を実行してパース。

### 2.3 VPN 復帰時再接続・省電力（F3）

**移植元**: `data/VpnController.kt`、`data/NetworkWatcher.kt`、`data/VpnTunnelProbe.kt`

- `cefapp/src/vpn_controller.mm`（新規）:
  - 可視性（前面/背面）と画面ロック（`com.apple.screenIsLocked` / `NSWorkspaceWillSleepNotification`）で
    ポーリング間隔を切替 — **Android の `ACTION_SCREEN_OFF` 相当**
  - スリープ復帰（`NSWorkspaceDidWakeNotification`）で即時検証
  - ネットワーク変化（`SCNetworkReachability` / `NWPathMonitor`）で 1.5 秒デバウンス後に再検証
  - 自動再接続（設定 `vpnAutoReconnect`、既定 ON）、クールダウン 30 秒
- 設定キー: `vpnSelectedProfileId` / `vpnAutoConnect` / `vpnAutoReconnect` / `vpnPowerSaver`
- **macOS 固有**: スリープ復帰は Android の「画面消灯」より確実に検知できる
  （`NSWorkspaceDidWakeNotification`）。ここは Android より有利。

### 2.4 サイト通知の定期監視（F4）

**移植元**: `data/SiteWatchRepository.kt`、`data/SiteFetcher.kt`、`notifications/SiteNotifier.kt`

### 2.5 ファイル/カメラ添付（F5）

## 3. タスク分解（依存グラフ）

```
WP-1 Rust core 移植（vpn_config / vpn_tuning / vpn_health / js_guard）  ← 他に依存なし
   │
   ├── WP-2 既存バグ修正（B1〜B20）＋ 設定のアトミック化
   │
   ├── WP-3 ブラウザ機能（F16 ダウンロード / F17 JS ダイアログ / F18 全画面 / F19-20 ズーム・Find）
   │
   ├── WP-4 VPN 統合（F1/F2/F3 — WP-1 に依存）
   │
   ├── WP-5 履歴・通知・ファイル添付・Web 通知（F4/F5/F6/F8）
   │
   ├── WP-6 設定画面・UI 適用（F10/F11/F12 + F14 自動入力）
   │
   └── WP-7 ローカライズ拡張（2.16）  ← WP-3〜6 の文字列が確定してから
```

**並列性**: WP-1 は独立。WP-2 は独立。WP-3 は独立。WP-4/5/6 は WP-1/2 の後。
WP-7 は最後。DSH の同時実行上限 2 に従い、**2 本ずつ直列化**する。

## 4. 受け入れ条件（AC）

| AC | 要件 | 検証方法 |

## 5. リスクと停止条件

| リスク | 影響 | 対処 |
|---|---|---|
| NetworkExtension が使えない | VPN の自前トンネル不可 | §0.1 で**実測により確定**。`wg` 連携＋疎通判定に限定し、UI で理由を明示 |
| `wg-quick` が root を要求 | 接続操作が失敗 | 起動時検出 + 案内。**クラッシュさせない**（AC-10） |
| CEF のコールバック寿命 | クラッシュ | `CefRefPtr` で確実にキャプチャ |
| ローカライズ 465 キー相当の拡張 | 作業量 | 既存 118 を維持しつつ、新規 UI 分だけ追加（Android 全 465 のうち Mac に存在する機能分） |
| DMG 157 MB | 配布 | 現状踏襲 |

**停止条件**: ビルドが通らない状態が 2 回続く / CEF の API 不整合で回避不能 / 署名で不可避な問題。

### 5.1 将来の拡張（有料開発者アカウントがある場合）

`com.apple.developer.networking.networkextension`（`packet-tunnel-provider`）を持つ署名で
`NEPacketTunnelProvider` を実装すれば、Android と同じアプリ内 VPN が可能になる。設計は：

- `core/` の Rust に `wireguard` 相当（`boringtun` crate）を組み込み、パケット処理を担う
- `NEPacketTunnelProvider` サブクラスが `NEPacketTunnelNetworkSettings` でアドレス/DNS/MTU を設定
- `wg` の設定テキストをそのまま `providerConfiguration` に渡す
- 疎通判定（§2.2）はそのまま再利用（`latest-handshakes` を provider から IPC で取得）

本計画では**この経路を実装しない**が、`vpn_health.rs` / `vpn_config.rs` を OS 非依存の純関数として
作るため、将来の差し替えは provider 層だけで済む。
